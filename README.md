# Плеяды 2026

Кейс-Чемпионат "Плеяды" от НЦКК и ФТМИ ИТМО

## Кейс от СТЦ

Обработайте снимки аппаратов форматов 3U и 12U: выполните цветокоррекцию, ортотрансформирование и геопривязку, устраните искажения и оцените пространственное разрешение. Для аппарата формата ЗU дополнительно объедините снимки в единую панораму и загрузите результаты в геоинформационную систему, например QGIS.
Затем с помощью компьютерного зрения обнаружьте на снимках облачность, населенные пункты, водоемы, промышленные объекты, аэродромы, нефтеперерабатывающие заводы и сельскохозяйственные угодья. Подготовьте отчет с оценкой качества распознавания
и анализом срате.

## Что сделано

- `scripts/orthorectify.py` рассчитывает наземные контрольные точки из
  положения и ориентации камеры, а GDAL строит GeoTIFF в проекции UTM.
  Для 12U используется ось камеры `+z`, для 3U — `-x`.
- `scripts/spatial_resolution.py` оценивает расчётный GSD исходных снимков
  либо шаг пикселя готовых GeoTIFF; данные разделены на центр и края кадра.
- Для 12U кадра `112-5-2025-10-09` получены PNG и GeoTIFF с подсветкой воды
  (`results/12u_water_112-5-2025/`) и выделением городской территории
  (`results/12u_urban_112-5-2025/`). Итоговые маски вычислены по яркости и
  текстуре **самого снимка**. Пробный вывод модели `sat-water` сохранён
  отдельно в `results/water_detection/` и не использован в итоговых масках.
- `scripts/google_maps_overlay.py` создаёт локальный просмотр TIFF на zoom
  12–13: `osm.html` показывает дороги OpenStreetMap без ключа,
  `index.html` — Google Maps после ввода ключа Maps JavaScript API.
  Карта используется для визуальной проверки, не для расчёта сегментации.
- В `results/12u_pitch_candidate/` сохранён диагностический вариант другого
  кадра (`112-10`) с компенсацией pitch. Точная привязка этого кандидата
  и кадра `112-5` по наземным контрольным точкам не подтверждена.
  Аэродром на кадре `112-5` не удалось уверенно распознать.

Исходники и телеметрия находятся в `data/`, ортотрансформированные TIFF и
предпросмотры — в `орто/`, экспериментальные и итоговые материалы — в
`results/`.

## Оценка пространственного разрешения

Скрипт `scripts/spatial_resolution.py` оценивает размер проекции пикселя на
земле (GSD, м/пиксель) в центральной области и в четырёх краевых полосах
снимка. Он также выводит среднее по всем краям, диапазон значений, класс
разрешения и отличие краёв от центра.

Для исходного снимка 12U используется модель камеры и парный файл телеметрии:

```powershell
python -X utf8 scripts/spatial_resolution.py camera "data\Снимки с MKA 12U\112-10-2026-10-12_06-45-09.99967-1791787509.jpg" --hfov-deg 20
```

Замените `20` на **калиброванный горизонтальный угол поля зрения камеры**.
Телеметрия автоматически ищется рядом со снимком по тому же имени. Для файла
с другим именем её можно указать через `--telemetry`. Высоту земной поверхности
над эллипсоидом можно задать через `--ground-height-m`.

Для проверки размера пикселя уже геопривязанного GeoTIFF:

```powershell
python -X utf8 scripts/spatial_resolution.py geotiff "орто\12u\112-10-2026-10-12_06-45-09.99967-1791787509_ortho.tif"
```

Для снимков 3U используется оптическая ось `-x`. Пример воспроизводимого
ортотрансформирования одного кадра:

```powershell
python -X utf8 scripts/orthorectify.py "data\Снимки с MK 3U\ANSAT-1\0-1-2026-02-03_03-55-30.00000-1770090930-Full.png" "орто\3u\ANSAT-1\0-1-2026-02-03_03-55-30.00000-1770090930-Full.tif" --hfov-deg 20 --camera-axis=-x --resolution-m 20
```

Для обработки всей папки и сохранения результатов для отчёта:

```powershell
python -X utf8 scripts/spatial_resolution.py camera "data\Снимки с MKA 12U" --hfov-deg 20 --json-output results\spatial_resolution.json
```

Полезные параметры:

- `--grid-size 21` — плотность сетки измерений;
- `--centre-fraction 0.20` — размер центрального квадрата (20% стороны);
- `--edge-fraction 0.10` — ширина каждой краевой полосы (10% стороны).

Режим `camera` показывает расчётный GSD исходного кадра и позволяет увидеть
изменение масштаба от центра к краям. Режим `geotiff` показывает шаг сетки
готового продукта: после ортотрансформирования и ресэмплинга он обычно почти
одинаков по всему изображению. Это геометрическая оценка, а не измерение MTF;
её точность зависит от калибровки HFOV, соглашения об ориентации, телеметрии и
модели рельефа.

Границы классов соответствуют приведённой в [статье EOSDA](https://eos.com/ru/blog/prostranstvennoe-razreshenie-sputnikovykh-snimkov/)
практической классификации: менее 1 м/пиксель — сверхвысокое, 1–5 — высокое,
5–30 — среднее, более 30 — низкое разрешение.

## Проверка привязки 12U на Google Maps

`scripts/google_maps_overlay.py` готовит локальный интерактивный просмотр
существующего GeoTIFF поверх карт Google или OpenStreetMap. Просмотр ограничен
zoom 12–13; можно менять прозрачность снимка и сравнивать берег, дороги и
населённые пункты. TIFF не отправляется поставщику карты.

Для кадра 12U из текущего набора просмотр уже можно собрать так:

```powershell
python -X utf8 scripts/google_maps_overlay.py `
  "results\group12\112-10-2026-10-12_ortho.tif" `
  --output-dir "results\12u_google_overlay"

python -m http.server 8000 --directory "results\12u_google_overlay"
```

После запуска откройте `http://localhost:8000/osm.html`: просмотр дорог
OpenStreetMap работает **без ключа**. Нужен доступ к интернету для загрузки
видимых тайлов и библиотеки Leaflet. Атрибуция OSM показана на карте; тайлы
загружаются только при просмотре, без предварительного скачивания.

Если нужен именно Google Maps, откройте `http://localhost:8000/` и вставьте
ключ с включённым **Maps JavaScript API** и настроенным billing. Для ключа
желательно задать ограничение HTTP referrer `http://localhost/*`.

Диагностический вариант TIFF с компенсацией угла pitch для кадра `112-10`
находится в `results/12u_pitch_candidate/`; его можно просмотреть тем же
способом через `osm.html` в этой папке. Это кандидат, привязка по дорогам
пока не подтверждена.

Google Maps здесь используется только для визуального контроля с сохранением
логотипа и атрибуции. Автоматически вычислять новую привязку из тайлов Google
нельзя: политика Map Tiles API запрещает image analysis, machine interpretation
и geodata extraction. Для автоматической коррекции следует использовать
разрешённый опорный набор (например, открытые данные Sentinel/Copernicus и OSM)
или собственные контрольные точки.

## Подсветка воды на кадре 112-5-2025

Для исходного 12U GeoTIFF можно воспроизвести PNG с синей подсветкой воды и
GeoTIFF с теми же координатами:

```powershell
python -X utf8 scripts/highlight_water_12u.py `
  "орто\12u\original_geotiff\112-5-2025-10-09_05-55-18.00000-1759989318_ortho.tif" `
  --output-dir "results\12u_water_112-5-2025"
```

Результаты: `water_highlight.png` для просмотра и
`water_highlight_georeferenced.tif` для GIS. Папка `map_view` содержит
наложение на карту дорог OSM (`osm.html`, без ключа) и Google Maps
(`index.html`, с ключом). Сегментация выполняется по яркости и текстуре снимка;
проверяйте мелкие каналы и тёмные участки суши вручную. Координаты копируются
из исходного TIFF: точность привязки Google для этого кадра не подтверждена.

Для этого же кадра `scripts/extract_urban_12u.py` создаёт
`urban_highlight.png` с оранжевой подсветкой застройки и `urban_only.png`,
где оставлена только застройка на прозрачном фоне. Варианты GeoTIFF находятся
рядом в `results/12u_urban_112-5-2025/`. Маска рассчитана по локальной
текстуре; это приближение, требующее проверки на парках и промзонах.

```powershell
python -X utf8 scripts/extract_urban_12u.py `
  "орто\12u\original_geotiff\112-5-2025-10-09_05-55-18.00000-1759989318_ortho.tif" `
  --output-dir "results\12u_urban_112-5-2025"
```

Аэродром в пределах данного кадра визуально не подтверждён. Координаты
исходного TIFF неточно согласуются с видимыми ориентирами, поэтому вырезать
аэродром только по координатам карты было бы ошибкой. Результат проверки
записан в `results/12u_urban_112-5-2025/airfield_assessment.md`.
